# SPEC — Peter's Pipeline Orchestrator v1.0 (the master, singular, channel-agnostic conductor)

*Design doc v2, 6 June 2026. Approved-in-discussion; this is the build reference for §11. Architecture altitude: every block is a black box with one job, one input, one output. Implements PART 2B + 2C of PIPELINE_PLAYBOOK.md. **Path 2** — new clean leg-based `orchestrate.py`; old six-phase conductor kept as `orchestrate_legacy.py` during transition; Final Hours moved onto the new machine only once it produces an identical result; then legacy retired.*

---

## 0. What this is

One conductor that runs the WHOLE post-script pipeline for ANY channel, end to end, until a finished video is scheduled in that channel's YouTube Studio. Nothing hangs off the end. It reads one spec (`beats.json`) + its metadata, discovers the channel and the work, runs only the legs the work needs around idiot-proof gates, narrates everything as telemetry at Peter's altitude, and finishes at "Publish & Schedule? y/n → DONE DONE."

Adding a channel that reuses existing legs = config only, zero orchestrator code.

The kickoff prompt is an **extensible block** — more questions can be added here later. For now: verbosity + dry/live.

`--log quiet|normal|verbose` and `--dry-run/--live` and `--from <leg>` bypass the prompt.

## 3. Inputs & preflight (halt EARLY, never fail at the end)

**Two input artifacts** (acknowledged not ideal — 1 would be cleaner; accepted for v1):
1. `beats.json` — the spec (channel header + per-beat mode/payload/narration/found_line/speaker/lock). From `parse_script.py`.
2. `<project>/metadata.json` — title, description, tags, privacy. Born WITH the script: generated by Claude during the thinking phase alongside the script, so it is never a forgotten manual step.

**Preflight (before any leg, before any spend) halts immediately with the fix if anything is missing:** beats.json present + parses; metadata.json present + has title/description/tags; channel.json resolves; venv active + run-from-channel-folder (fail loudly with the fix, not a cryptic ImportError); required tools present. A missing metadata.json halts AT KICKOFF with the template to fill — not 40 min and $8 later.

---

## 4. The two reads (orthogonal: composition picks machinery, channel picks look)

1. **Read `channel`** → load `<channel>/channel.json`, resolve `<project>/look.json` ON TOP (channel defaults → project overrides; most channels have none, Lazarus is built on it) → **resolved config** every leg reads.
2. **Scan composition** → decide legs: any A → Mode A leg + Mode A gate; any B → Mode B leg + Mode B gate; any locked → lip-sync leg (future); always → audio leg first. Every decision is logged as a teaching line.

---

## 5. The legs (black boxes: input → output, one job, no cross-knowledge)

| Leg | Input | Output | Gate | Status |
|---|---|---|---|---|
| **Audio** (first) | beats + cfg | voiceover.mp3 + durations.json + captions.srt | **Audio gate** | ✅ built (2a-2d); +SRT, +keep/swap |
| **Mode B** | beats(B) + cfg + durations | clips/beat_NN_B_*.mp4 | **Mode B gate** | ✅ render proven; +gate |
| **Mode A** | beats(A) + cfg + durations | clips/shot_NNN.mp4 + index map | **Mode A gate** | translate+ingest ✅; full render = build |
| **Lip-sync** | locked beats + cfg | synced clips | (future) | not built |
| **Convergence** | all clips + durations + VO + music + metadata + thumbnail | scheduled YouTube video | **Convergence gate** | build |

Audio first (timing source). A and B in either order after (share nothing). Convergence last. A leg never calls another; the orchestrator alone knows the sequence.

## 6. Audio gate — KEEP or SWAP (the human-voice decision, brought to the front)

After the audio leg produces Victor's VO + durations + SRT, the gate asks:

```
  ┌─ AUDIO GATE ──────────────────────────────────────────────┐
  │ Pipeline produced voiceover.mp3 — measured 10.8 min.       │
  │ [1] KEEP  — use this Victor read, carry on.                │
  │ [2] SWAP  — replace with your own (human) recording.       │
  └────────────────────────────────────────────────────────────┘
  >>> [1/2]:
```
- **KEEP** → carry on; durations.json already built; nothing changes.
- **SWAP** → idiot-proof copy-paste to move the human file from laptop Downloads → box, then the orchestrator **re-runs Whisper on the human audio and REBUILDS durations.json + captions.srt** from it, so every downstream beat hangs off the real human timing:
```
  │ LAPTOP terminal — paste:                                   │
  │   scp -P 443 ~/Downloads/voiceover.mp3 \                   │
  │     peter@116.202.18.68:~/Pipeline/synthetic/projects/ep1-the-promise/voiceover.mp3
  │ Then type 'done' here — I'll re-measure timing from it.    │
  >>> type 'done' when the file is in place:
```
**Why this kills the true-up:** drift only ever happened because timing was a word-count guess. Now timing is MEASURED from whatever audio is final (Victor or human), before any visual is built, so the beat timestamps carry all the way through. The assembler always holds each clip to its measured duration — so **the assemble step IS the sync-correct step, every run, for both KEEP and SWAP.** No separate end true-up; that concept collapses into "the assembler always uses measured durations." (One home, one job.)

## 7. Mode B gate — autoplay review + live payload-edit & one-click re-render

Mirrors the stills gate, but Mode B's determinism unlocks something better: an in-page
**edit-and-fix surface**. The orchestrator builds **one scrollable HTML page** embedding
all Mode B clips, **autoplay + loop + muted** — scroll top→bottom, everything plays, zero
clicks to watch. But beside each playing clip sits a live-fix panel:

```
  ┌─ beat 12 · NumberCounter ──────────────┬───────────────────────────┐
  │                                         │ PAYLOAD (editable):       │
  │     [ the clip, autoplaying, looping ]  │   endValue: 1997          │
  │                                         │   prefix:  ""             │
  │                                         │   label:  "Deep Blue…"    │
  │                                         │   ─ duration: 3.0s (LOCKED)│
  │                                         │ SPOKEN (read-only):        │
  │                                         │   (silent beat — no VO)    │
  │                                         │ [ Re-render this beat ]    │
  │                                         │ [ Flag: audio-affecting ]  │
  └─────────────────────────────────────────┴───────────────────────────┘
```

**How it works.** The editable box is the beat's **payload JSON** (the content props —
the number, the text, the attribution, the highlight). Edit `1,997`→`1997` or fix a typo,
click **Re-render this beat** → the orchestrator runs `dispatch.py --only N --render` with
the edited props → the clip hot-swaps in place a few seconds later ("magical seconds" — a
real Remotion render, not instant, but vastly faster than looping back through the pipeline).
This is the 90% case: a card content error that the audio does not depend on. Fix it here,
move on.

**Two structural safety rules (the gate makes the dangerous thing impossible, not just discouraged):**
1. **Duration is shown but NOT editable.** Frame count comes from `durations.json` (locked by
   the audio leg). The edit box never exposes it, so a re-render physically cannot change how
   long the card holds — the audio↔visual sync can't be broken from this gate, by construction.
2. **The beat's SPOKEN line is shown read-only beside the payload.** This is the awareness
   mechanism for the one error this gate CANNOT fix: if the *narrator says* the wrong thing
   (the audio depends on the content), correcting the card here would desync card from voice.
   Seeing the spoken line next to the payload tells you at a glance which kind of error you
   have — **card-only (fix here)** vs **audio-affecting (loop back)**.

**The two error paths:**
- **Card-only / payload error** (typo, 1,997, wrong on-screen attribution; audio unaffected)
  → edit payload → Re-render → hot-swap. Self-contained, no loop-back.
- **Audio-affecting error** (the spoken line itself is wrong) OR **render bug** (Remotion/
  component fault, not fixable by payload) → **Flag** → marks the beat for loop-back: correct
  `script.md`, re-run the audio leg (because timing changes), re-render. The gate is explicit
  that this path is the expensive one — which is exactly why it reinforces the rule below.

**There is no "AI fix" here** (unlike stills): a Mode B card is deterministic from its payload,
so the fix is *edit the data*, not *ask AI to redraw*. The gate loops until you confirm all clips ok.

**Why this is a game-changer (and why the script must be locked).** Once all nine Mode B
components exist, this becomes a fast confirm/fix surface for every graphic in an episode —
work down the page, fix basic errors in seconds, never touching the pipeline. But it also makes
something mechanically true that great filmmakers know by instinct: **the script is load-bearing.**
The audio is measured from the script; every visual timing hangs off that audio; this gate can
fix a misspelled card in seconds but CANNOT fix a wrong spoken line without looping all the way
back. The architecture physically enforces "lock the script first" — which is *why* great films
start from a great script: everything downstream is timed and bound to it.

**Phase 2 upgrade (noted, not built):** truly-live preview (edit reflects instantly, no
re-render wait) would use the Remotion Studio/Player dev server rather than `--only` re-renders.
Bigger build; revisit once the 9-component library is complete.

## 9. CONVERGENCE (assemble + upload — the end-to-end finish, nothing hangs off after)

The whole point: when the orchestrator finishes, there is a scheduled video in the channel's Studio. Convergence = assemble → thumbnail gate → convergence gate → upload+schedule → DONE.

### 9.1 Assemble (one home for all final-video assembly)
- **Interleave** all clips in true beat order via the index map.
- **Hold each clip to its measured duration** (durations.json) — this IS the sync-correct step (see §6).
- **Music**: ducked bed under the VO, ported mux from the engine's assemble() — `VOICE_LEVEL 1.15` / `MUSIC_LEVEL 0.07`, loop-to-cover, bed from channel.json `default_music_prompt` (or `--music`/`--no-music`).
- **Long-beat handling** (banked issue): a beat whose measured duration ≫ one Kling clip (~5s) holds/slows or is broken into sub-shots — decided here.
- Output: `final_video.mp4` at channel resolution (1080p Synthetic). Telemetry: trimmed N/N (one updating line), concat, mux, final duration.

### 9.2 Chapters (straight from the script — no derivation logic)
**Chapters are authored as `ChapterCard` beats** (Synthetic already has them; any channel that wants chapters writes them — reuses the existing Mode B component, no new syntax). Convergence emits `MM:SS Title` per ChapterCard from durations.json timestamps, prepends `0:00 Introduction` if the first card isn't at zero (YouTube requires a 0:00 chapter), and injects the lines into the description. Short videos with no ChapterCards get no chapters. This nudges toward long-form (the strategy) and is neater than logic-derived chapters.

### 9.3 SRT captions
Built by the audio leg from **script-aligned Whisper timings** (Whisper's word *timestamps*, but the script's *words* — correct spelling + correct sync, fixing the old caption-sync deletion problem). Attached at upload.

### 9.4 Pre-convergence THUMBNAIL gate (manual step, NO skip — golden rule)
Thumbnail is made manually (Clickly). Convergence STOPS and will not proceed until `thumbnail.png` exists in the project folder. **No "upload without thumbnail" option** — that road leads to a pile of Studio videos needing thumbnails later (wrong mode). Worst case: a first-draft thumbnail now, replace later.
```
  ┌─ THUMBNAIL GATE ──────────────────────────────────────────┐
  │ Move your thumbnail from laptop Downloads → box. LAPTOP:   │
  │   scp -P 443 ~/Downloads/thumbnail.png \                   │
  │     peter@116.202.18.68:~/Pipeline/synthetic/projects/ep1-the-promise/thumbnail.png
  │ Then type 'done'. (Cannot proceed without it.)             │
  └────────────────────────────────────────────────────────────┘
  >>> type 'done' when thumbnail is in place:
```
(Checks the file exists; if not, repeats — no bypass.)

### 9.5 Convergence gate (review everything going live → DONE DONE)
Asks the **schedule date** — DDMM only (4 digits); time defaults to **01:00 CET** (channel default, overridable later). Then displays the complete upload manifest for confirmation (metadata is DISPLAYED from metadata.json, not entered — confirm not data-entry):
```
  ┌─ CONVERGENCE GATE ────────────────────────────────────────┐
  │ channel:    synthetic                                      │
  │ title:      The Promise — How OpenAI Began (Ep.1)          │
  │ description: [first 2 lines…] + 5 chapters + links         │
  │ tags:       openai, ai history, sam altman, … (12)         │
  │ thumbnail:  thumbnail.png ✓ present                        │
  │ captions:   captions.srt ✓ (script-aligned)                │
  │ schedule:   2026-06-14 01:00 CET   (you entered 1406)      │
  │ privacy:    scheduled (private until go-live)              │
  │ video:      final_video.mp4  10.8 min  1080p  148 MB       │
  └────────────────────────────────────────────────────────────┘
  >>> Publish & Schedule? [y/n]:
```
`y` → uploads via the universal uploader → **DONE DONE: scheduled in Studio.**

### 9.6 Universal upload black box (the new build — replaces the channel-specific script)
One uploader, channel-agnostic. Takes the resolved channel; loads **that channel's** YouTube OAuth token from the channel folder (gitignored; first-time per-channel auth is a documented one-time MANUAL setup — Claude never handles auth tokens/credentials, that's Peter's per-channel setup). Uploads `final_video.mp4` with metadata + chapters-in-description + SRT + thumbnail, scheduled at the chosen datetime, privacy=private-until-go-live. So **upload identity lives with the channel, like every other identity** — the answer to the "come back to this" question.

## 10. Telemetry (threads through everything)

Altitude = orchestrator, not implementation. One `telemetry.py` log helper (one home, all formatting). **~20 lines visible at a time** — paced so a phase fits roughly a screen; long loops summarize to ONE updating line ("trimmed 41/41"), never 41 lines. Verbosity dial set at kickoff (§1).

Line vocabulary (visually distinct, reads as a story):
```
  ━━ AUDIO LEG ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━   phase header
  ✓ whisper aligned → 588.5s, 39 beats timed            step + result + metric
  → composition: Mode B present → Mode B leg WILL run    decision (teaching line)
  ℹ durations: 39 measured, 23 silent-hold               metric
  $ Mode A: 41 stills (~$1.23 fal)                       cost marker
  ⏸ AUDIO GATE — keep or swap?                           gate stop
  ⚠ beat 42 countdown unsupported (renders 0→44M)        warning, non-fatal
  ✗ HALTED: metadata.json missing — fill template, rerun fatal, halts
```
**End-of-run summary** (one screen, nothing lost to scroll): channel/project, legs run + clip counts, episode length/res/size, cost, warnings, and the final line: `scheduled → 2026-06-14 01:00 CET in synthetic Studio`.

## 11. Build order (each tested before the next — the session rhythm)
1. `banner.py` + run-context + `telemetry.py` + **kickoff prompt** (verbosity + dry/live). The skeleton speaks first — first run prints banner, asks the two questions, narrates which legs it WOULD fire, costs nothing.
2. `load_resolved_config()` (channel.json + look.json) + `decide_legs()` (composition scan) + **preflight** (incl. metadata.json check). Pure, testable, logs decisions.
3. Conductor flow calling the BUILT audio leg (+ audio gate keep/swap) and the proven Mode B render leg (+ Mode B autoplay gate), gates real, `--dry-run` then live on Mode B only.
4. Mode A leg + Mode A (stills) gate.
5. **Convergence**: assemble (interleave + music + chapters + SRT) → thumbnail gate → convergence gate → universal uploader + schedule.
6. `--from`, verbosity polish, end-summary.
7. Final Hours validated last as the Mode-A-only signature; once identical to legacy, retire `orchestrate_legacy.py`.

## The one-line mental model
**Banner → ask verbosity + dry/live → preflight the spec + metadata → load the look → decide the legs → audio (keep or swap, re-measure) → renderers around autoplay/stills gates → converge (assemble + chapters + SRT → thumbnail gate → review everything → Publish & Schedule y/n) → a scheduled video in Studio, narrated at your altitude the whole way.**

*(Load-bearing truth the architecture enforces: the script is locked because the audio is measured from it and every visual timing hangs off that audio. The Mode B gate fixes card content in seconds but cannot fix a wrong spoken line without looping back — which is why, mechanically here as in filmmaking, everything starts from a great, locked script.)*
